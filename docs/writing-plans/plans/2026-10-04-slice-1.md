# Slice 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shep dog that serves every model on the GPU host behind one HTTP endpoint, admits models by declared footprint, protects leased models from eviction, and refuses what cannot be served with a reason.

**Architecture:** A pure, synchronous `Book` holds every decision: which model is loaded, who waits and why, which lease holds what. It takes `Event`s and returns `Action`s, so all of the design session's rules are tested by table with no I/O. An async engine task owns the `Book`, runs its actions against two backends (shep sheep, and ollama through its API), and feeds results back as events. A hyper server turns HTTP into engine commands, and the same binary run with arguments is the `shep paddock` CLI.

**Tech Stack:** Rust 2024, MSRV 1.88, tokio (current-thread), hyper 1 + hyper-util + http-body-util (server), reqwest 0.13 (backend and CLI client), shep-client 0.12 (shepherd socket, dog probe, `#[dog_config]`), serde/serde_json/toml, schemars, jiff, subtle.

**Spec:** `docs/brainstorming/specs/2026-10-04-slice-1-design.md`. Vocabulary: `CONTEXT.md`. Decisions: `docs/adr/0001` to `0003`. Read all three before Task 1.

## Review Focus

The failure modes the spec implies but no task's own behaviour tests would reach. Each line's test lives in the named task.

1. A client that disconnects in the middle of a streamed (SSE) response must still end that request's in-flight count, or the model can never be evicted or idle-unloaded. Test in Task 9.
2. A request body that is not JSON, has no `model`, or is larger than the body cap gets a `400` or `413` at once, never a hang and never a forward. Test in Task 9.
3. A config reload that removes a model which is loaded or leased: new requests for it get `404`, existing leases on it keep it loaded until they end, and then it unloads. Test in Task 5.
4. The shepherd connection drops (`shep daemon reload`): the `process.*` subscription ends with it and must be re-armed, or a crashed backend goes unnoticed. Test in Task 7.
5. `state.json` that is corrupt, or from a newer version: the dog starts with no leases and logs why, instead of crash-looping under shep's restart backoff. Test in Task 11.

```rust
/// Milliseconds since the engine started. The Book never reads a clock.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub struct Moment(pub u64);
impl Moment { pub fn plus(self, d: Duration) -> Moment; pub fn since(self, earlier: Moment) -> Duration }

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct WaiterId(pub u64);
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct LeaseId(pub u64);

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub enum Priority { Interactive, Batch }   // Interactive sorts first

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum State { Unloaded, Reserved, Loading, Loaded, Evicting, Unloading }

pub enum Event {
    RequestArrived { waiter: WaiterId, client: ClientName, model: ModelName, priority: Priority, max_wait: Duration },
    WaiterGone { waiter: WaiterId },
    RequestFinished { model: ModelName },
    Loaded { model: ModelName },
    LoadFailed { model: ModelName, error: String },
    Unloaded { model: ModelName },
    BackendExited { model: ModelName },
    // Lease events are added in Task 4.
    Tick,
}

pub enum Action {
    Load(ModelName),
    Unload(ModelName),
    Forward { waiter: WaiterId, model: ModelName },
    Refuse { waiter: WaiterId, refusal: Refusal },
    Fail { waiter: WaiterId, error: String },
    Waiting { waiter: WaiterId, reason: Reason, estimate: Option<Moment> },
    Persist,
}

pub enum Reason {
    Loading { model: ModelName },
    Evicting { model: ModelName, for_model: ModelName },
    Draining { model: ModelName },
    Grace { model: ModelName, until: Moment },
    Held { model: ModelName, client: ClientName, lease: LeaseId, until: Option<Moment> },
    Behind { model: ModelName },
}

pub struct Refusal { pub reason: Reason, pub retry_after: Option<Duration> }

pub struct Book { /* config: Arc<Config>, slots: BTreeMap<ModelName, Slot>, waiters, leases, errors */ }
impl Book {
    pub fn new(config: Arc<Config>) -> Book;
    pub fn handle(&mut self, now: Moment, event: Event) -> Vec<Action>;
    pub fn next_deadline(&self) -> Option<Moment>;
    pub fn state(&self, model: &ModelName) -> Option<State>;
}
```

The rules this task implements, from the spec's "Admission" section:

1. `RequestArrived` for a model in `Loaded`: `Forward` at once, `in_flight += 1`, `last_used = now`.
2. Otherwise the request joins the waiters, and `reconsider(now)` runs. `reconsider` runs after every event.
3. `reconsider` walks waiters in `(priority, arrival)` order. Per waiter, by its model's state:
   - `Loaded`: admit it (`Forward`).
   - `Reserved`, `Loading`: it waits with `Reason::Loading`.
   - `Evicting`, `Unloading`: it waits with `Reason::Evicting` or `Reason::Draining`.
   - `Unloaded`: if the model fits beside every model in `Reserved`, `Loading`, `Loaded`, `Evicting` or `Unloading`, and no exclusion pairs it with one of them, it turns `Loading` and the Book emits `Load`. If not, it looks for an eviction set (rule 4). A blocked waiter never stops the walk, so a later waiter whose model fits is still served (skip-ahead).
4. Eviction set: candidates are `Loaded` models that no lease names (leases arrive in Task 4, so in this task every loaded model is a candidate). Sort by `last_used` ascending, add until the waiter's model fits and no exclusion remains, then drop any chosen model the fit does not need, in reverse order. If a set exists, the eviction is committed: each model in it turns `Evicting` (or `Unloading` at once, emitting `Unload`, when its `in_flight` is 0), and the waiter's model turns `Reserved`. `Reserved` counts in the totals, so nothing else takes the room being freed.
5. `RequestFinished` lowers `in_flight` and sets `last_used = now`. An `Evicting` model reaching 0 turns `Unloading` and emits `Unload`.
6. `Unloaded` turns the model `Unloaded`. A `Reserved` model whose evictions are all done turns `Loading` and emits `Load`.
7. `Loaded` turns the model `Loaded` and remembers the load's duration for estimates (`Loading` start to now).
8. `LoadFailed` on the first attempt emits `Load` again. On the second it turns the model `Unloaded`, emits `Fail` for every waiter on it, and pushes `(model, now, error)` onto `errors` (keep 20).
9. `BackendExited` while `Loaded` or `Evicting`: turn `Unloading`, emit `Unload` (for a sheep, this stops it so autorestart cannot bring it back). While `Loading`: treat as `LoadFailed`.
10. A waiter's `Reason` is emitted as `Waiting` only when it changes from the last one emitted for that waiter.

Rules, from the spec's "Leases" and "Waiting, refusal, estimates" sections and the design session's answers:

1. A lease is a waiter until granted. It is granted when its model is `Loaded`, loading it first through Task 3's rules if needed. From grant until it ends, its model is held: never an eviction candidate, never idle-unloaded.
2. Interactive waiters go before batch ones. Within a level, arrival order (Q10).
3. A batch waiter may only evict a model unused for at least `config.grace` (`now - last_used >= grace`). If the only eviction set needs a model still inside its grace period, the waiter waits with `Reason::Grace { until }`, and `next_deadline` includes `until`.
4. A model named by a granted lease blocks with `Reason::Held { client, lease, until }`, where `until` is `since + expected` when the lease gave one.
5. Estimates: `Loading` is the loading start plus the model's last load duration (60 s before the first load). `Held` is `until`. `Grace` is `until` plus a load. `Behind` is the estimate of the waiter ahead, when it has one. Otherwise `None`.
6. Requests have a deadline of `arrival + max_wait`. At arrival and at every reconsider, a request is refused (`Action::Refuse`) when its block is `Held` with `until: None`, or its estimate is past its deadline. On reaching its deadline it is refused with its current reason. `retry_after` is `estimate - now` when there is one. A lease is refused the same way only when it set `max_wait`.
7. Heartbeat leases end `Expired` when `now >= last_renewal + ttl`. `LeaseRenewed` moves `last_renewal`.
8. Connection leases: `HolderDetached` starts the reconnect window. `HolderAttached` inside it clears it. At `detached_at + config.reconnect` the lease ends `Abandoned`.
9. `LeaseReleased` ends a lease `Released` at once. Every end emits `LeaseEnded` and `Persist`, and every grant emits `Persist`.
10. Idle unload: on any event, a `Loaded` model with no lease, `in_flight == 0`, no waiter, and `now - last_used >= model.idle` emits `Unload`. `next_deadline` includes the earliest such moment.
11. `next_deadline` is the minimum of request deadlines, grace ends that matter to a waiter, heartbeat expiries, reconnect window ends and idle-unload moments.

### Task 10: Lease routes

**Files:**
- Create: `src/http/lease.rs`
- Modify: `src/http/mod.rs`

**Interfaces:**
- Consumes: `EngineHandle::{take_lease, attach, renew, release}`, `LeaseEvent`.
- Produces: routes `POST /paddock/leases`, `POST /paddock/leases/{id}/attach`, `PUT /paddock/leases/{id}`, `DELETE /paddock/leases/{id}`.

Behaviour, from the spec's "Leases" section:

- `POST /paddock/leases` body `{model, priority?, expected?, note?, hold?, ttl?, max_wait?}` with `deny_unknown_fields`; durations in the UpDuration grammar; `hold` is `"connection"` (default) or `"heartbeat"`. Unknown model `404`; a model that can never fit was refused by config validation, so it cannot reach here.
- Connection hold: `200` with `content-type: application/x-ndjson`, one JSON object per line: `{"queued": {"reason": "...", "estimate": "...|null"}}` on each `Waiting`, `{"granted": {"id": "L7", "reconnect": "60s"}}` (the spec's `granted` plus the window the holder has to attach again, which the CLI needs), then `{"heartbeat": {}}` every `STREAM_HEARTBEAT = 15 s`, then `{"ended": {"why": "released|expired|abandoned"}}` and end of body. A refusal is `{"refused": {...the busy body...}}` and end of body. The response body owns the engine receiver, so a hang-up drops it and the engine sees `HolderDetached`.
- Heartbeat hold: the request waits like the streamed form, then `200 {"id": "L7", "ttl": "60s"}`.
- `attach`: the same stream, starting with `{"granted": {"id": ...}}`. `404` if the lease does not exist (`LeaseRefused::NotFound`), `403` if it is another client's (`NotYours`), `409` if a holder is already attached (`Attached`).
- `PUT`: renew, `204`. `DELETE`: release, `204`. Same `404` and `403`.
- Lease ids render as `L<n>` and parse back strictly.
